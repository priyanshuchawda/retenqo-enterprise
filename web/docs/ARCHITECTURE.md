# Website Architecture

## Overview

The Retenqo website is a **fully static site** built with [Astro](https://astro.build/). It has zero runtime server-side logic, no database, and no user accounts. All HTML is generated at build time and served as static files via Cloudflare Pages.

## Technology stack

| Layer       | Choice                      | Rationale                                       |
| ----------- | --------------------------- | ----------------------------------------------- |
| Framework   | Astro 7 (static output)     | Static HTML with small local scripts   |
| Language    | TypeScript (strictest mode) | Type safety, maintainability                    |
| Styling     | Tailwind CSS v4             | Utility-first, design tokens, purged output     |
| Validation  | Zod                         | Schema-validated release metadata at build time |
| Testing     | Vitest + Playwright         | Unit + end-to-end browser coverage              |
| Package mgr | pnpm (frozen lockfile)      | Reproducible installs                           |
| Hosting     | Cloudflare Pages            | Edge CDN, free HTTPS, no server                 |
| Deployment  | Wrangler CLI                | `wrangler pages deploy web/dist`                |

## Data flow

```
GitHub Releases API
      │
      ▼
scripts/sync-release.ts   (verify digest, package, signer)
      │
      ▼
src/data/release.generated.json   (committed, schema-validated)
      │
      ▼
Astro build (pnpm build)
      │
      ▼
dist/   (static HTML/CSS/JS)
      │
      ▼
Cloudflare Pages (edge CDN)
      │
      ▼
User browser (zero backend)
```

## Security headers

Served via `public/_headers` (Cloudflare Pages):

- `Content-Security-Policy` — restricts script/style/image/connect sources
- `Strict-Transport-Security` — HSTS with 1-year max-age
- `X-Frame-Options: DENY`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: no-referrer`
- `Permissions-Policy` — disables camera, microphone, geolocation at browser level

## Release metadata

The file `src/data/release.generated.json` is generated by `scripts/sync-release.ts` using the GitHub Releases API. It is schema-validated by Zod schemas in `src/lib/releases/validation.ts`. The website supports a pending state for initial distribution and preserves previously verified metadata when synchronization fails. Current metadata describes v0.1.4. See the [engineering audit](ENGINEERING_AUDIT.md) for the verification scope.

## Assumptions

- No server-side rendering needed — content is static.
- APK is distributed via GitHub Releases only — no self-hosted binary distribution.
- No analytics, A/B testing, or feature flags.
- Wrangler must be authenticated interactively before deploy.
