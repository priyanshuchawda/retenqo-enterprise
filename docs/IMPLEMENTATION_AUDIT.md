## Device validation update — 2026-11-24

- Connected handset is a Samsung SM-M325F / Galaxy M32 running Android 13 (API 33), not the Galaxy M34 target.
- The installed Qwen3.5-0.8B Q4_0 GGUF was verified at 563,036,064 bytes and loaded with the app's llama.cpp CPU backend. Initial native logs showed `no backends are loaded`; building the CPU backend into the runtime fixed that failure.
- `What is two plus two` returned `Two plus two equals four.` with Wi-Fi and mobile data disabled. A loaded-process PSS sample was about 831 MB; observed model load times ranged from 1.1 to 3.7 seconds. These are basic observations, not repeatable device benchmarks.
- Hash-based semantic scoring produced a false match against an unrelated Pulse card. Retrieval was changed to meaningful lexical overlap and a regression test was added. The existing card was left on-device.
- The app manifest includes `INTERNET` for explicit model download. After weights are installed, model generation and local search were verified without network access.
- The phone's Wi-Fi and mobile data settings were restored after the offline check.

## Baseline limitations

- No model files are tracked in this checkout. A compatible file was installed in the connected app's own storage for device validation.
- Device capture, microphone, alarm delivery, WhatsApp notification intake and the Galaxy M34 performance target remain unverified.
- Current rubric pass: Android unit tests, debug assembly, and Android Lint pass (74 unit tests, 0 failures/errors/skips; 27 non-blocking Lint findings). One Android crypto instrumentation test passed on the Galaxy M32. The latest APK installed and launched, and `git diff --check` is clean. Gradle 8.14.3 will need upgrading before Kotlin 2.5.0.
- Android 14 media access now requests `READ_MEDIA_VISUAL_USER_SELECTED` alongside full image access and treats either grant as media availability. Model lookup no longer walks shared-storage paths; downloaded/imported weights remain app-scoped.
- New backups encrypt the export envelope with AES-256-GCM and a PBKDF2-HMAC-SHA256-derived 256-bit key. The password is not persisted; older Retenqo JSON backups still restore. JVM crypto round-trip/tamper/password tests pass, and the Android crypto-provider round-trip/wrong-password test passes on the M32.
- `./scripts/build-mneme.sh` produced a 103 MB ARM64 debug APK. The first native build found missing ignored source checkouts, CMake/NDK mismatches, an incomplete Whisper CMake source list, and CPU backend plugin discovery failure. Pinned bootstrap, the upstream Android stub source, local build settings and linking the CPU backend into the runtime resolved these. The manifest includes `INTERNET` for the explicit model download feature; local inference was verified with Wi-Fi and mobile data disabled.
- The repository's existing `MODELS.md` and evaluation report contain useful model experiments, but host-side results and the single Galaxy M32 run are not Samsung Galaxy M34 benchmarks.
- Recent merged history includes card schema, rules-first extraction, ingestion, briefing, and Ask work (#26–#31), followed by a Gemini/UI migration. The checked-out implementation therefore does not satisfy the requested all-offline architecture despite some older docs describing on-device behavior.
